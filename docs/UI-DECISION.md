## Resource investigation, 12 November 2026

The official `Microsoft.WindowsAppSDK.WinUI.CSharp.Templates` 0.0.8-alpha WinUI Blank App was generated for comparison. The template's package-install post-actions failed under restricted network access, so it was inspected, not built. It uses the same .NET target, minimum platform version, `UseWinUI`, `XamlControlsResources`, and `InitializeComponent` / `OnLaunched` pattern. It defaults to MSIX tooling, assets and an application manifest; Xplorer currently uses unpackaged self-contained output. The two project configurations are not identical.

A fresh copy of the actual WinUI project and shared sources was built under ignored `obj/resource-investigation/` with the copy target removed. This isolated output contained `Xplorer.WinUI.pri` and SDK PRI files, but no `resources.pri`. It started and all nine UI Automation smoke checks passed against that output on Windows build 26300. The build had two NU1900 warnings because vulnerability metadata could not be fetched; cached dependencies restored. This does not establish why the earlier blank prototype failed, prove all theme resources or visible rendering work, or validate publishing and other Windows versions. The earlier failure was not reproduced under the current conditions. Keep the copy rule until the chosen distribution path is verified on the intended Windows 10 and Windows 11 versions as requested.

Follow-up: nuget.org TCP port 443 was unreachable in the agent's restricted execution environment but reachable outside it. A forced, no-cache restore of the main WinUI project with network access completed without warnings. The repository source was already correct. This does not permanently change the agent's sandbox network policy; future operations may again need network access approval. This follow-up restored the main project, not the isolated investigation build.

Afterward, at the user's request, local Codex configuration was updated to set `sandbox_workspace_write.network_access = true`. The current session still could not reach nuget.org from inside its sandbox. Verify in a new session whether the setting takes effect or a managed permission profile overrides it; use approved network access for restore if necessary.

Microsoft documents both [unpackaged self-contained deployment](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/unpackage-winui-app) and [resource indexing for unpackaged applications](https://learn.microsoft.com/en-us/windows/apps/winui/winui3/localize-winui3-app). These references do not by themselves identify the original failure. Further work: choose and build the actual distribution artifact, inspect resource and theme behavior visibly, run the UI and file-action checks against that artifact on Windows 10 and Windows 11, then remove the copy target only after those checks pass.
