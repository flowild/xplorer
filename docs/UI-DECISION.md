# UI technology evaluation

The current application remains a WPF prototype while WinUI 3 is evaluated. WPF already builds in the present environment and supports the prototype's existing navigation and Windows integration. WinUI 3 is Microsoft's recommended native UI framework for new Windows apps and would offer modern Windows controls, but migration requires a Windows App SDK build environment and a separate working prototype before a final decision.

Microsoft documents Windows 10 version 1809 (build 17763) as the minimum for the Windows App SDK; the chosen SDK, .NET runtime, packaging approach and exact supported Windows releases still need to be verified together before release. Sources: [Windows versions and SDK overview](https://learn.microsoft.com/en-us/windows/apps/get-started/versioning-overview), [WinUI 3](https://learn.microsoft.com/windows/apps/WinUI), and [Windows App SDK support](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/support).

On 12 November 2026, the configured nuget.org feed was reachable outside the agent's restricted network environment. The `Microsoft.WindowsAppSDK.WinUI.CSharp.Templates` 0.0.8-alpha template was installed in the workspace-local .NET environment; a separate, generated blank WinUI app restored and built for win-x64 without warnings. The test project resides under ignored `obj/` and was not integrated into Xplorer. This is not a performance or compatibility comparison. Build a small navigation/list prototype and compare startup, large-folder behavior, accessibility, shell integration, packaging and Windows 10/11 behavior before deciding whether to migrate. Future package downloads in the agent's restricted environment require network access; no global NuGet configuration was changed.

The packaged test launch requires Windows Developer Mode. An initial unpackaged, self-contained launch failed because WinUI could not locate its theme resources. In the temporary build output, copying `Microsoft.UI.Xaml.Controls.pri` to `resources.pri` allowed the hidden test process to stay running for three seconds. This is an experimental diagnostic workaround, not a validated packaging solution; the visible UI and full resource behavior still need verification. The temporary output is not a committed prototype and may disappear during cleanup.

At the user's request, `WinUI/` now contains a separate experimental port using shared filesystem and search code. Its build uses the same tentative resource workaround. The application has built and a hidden smoke test produced a window, but its UI, file operations and distribution have not yet been validated interactively. The WPF application remains available while the port is checked.
